# AI 協作流程

## 共用入口

不同 Agent 不一定自動讀 AGENTS.md。第一次啟動時貼上 docs/05_AI啟動提示詞.md，讓工具明確讀取規範；後續加入各工具設定時，只引用共用文件。Unity MCP 可作為選配的 Editor 操作工具，並非本範本必備依賴；先確定工具支援本 Editor，且只在已授權的專案範圍工作。

## 一個任務的完整週期

1. 老師或同學在 Issue 說明希望玩家看到什麼，使用任務範本列出驗收條件。
2. AI 先確認現況，提出最小修改計畫；大範圍或未決定的需求先釐清。
3. 在任務分支實作。每個 PR 聚焦一個功能；不把無關升級一起加入。
4. 編譯、Play Mode 驗證、必要的 EditMode/PlayMode 測試及適當 Build。
5. AI 在 PR 寫明檔案變更、Inspector 操作、驗證證據與待辦；另一位審查者或老師 review。
6. 老師決定合併。若 AI 沒有 Editor，老師完成實機驗證後再核准，不以文字報告取代實際操作。

## 避免教學被 AI 取代

每次交付要求 AI 解釋一個核心概念、指出 Inspector 需要設定的地方，並給同學一個小練習。同學需能說明程式何時執行、資料從哪裡來、如何測試；不要只複製程式。

CI 第一階段可先做文件或靜態檢查。Unity 自動測試與 Build 涉及授權、執行環境與平台模組，待本地專案可重現後再設計，不預先放入看似通過的空 CI。
